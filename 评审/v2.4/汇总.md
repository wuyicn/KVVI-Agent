## 一、本轮做了什么

前三轮的八份评审分别从逻辑、安全、对抗性、完整性、可行性视角审。本轮换一个
**此前没被覆盖的视角**：**实现者视角**——"我明天作为开发者拿到这份文档，
能不能直接开工？开工会撞上什么？"

| 项 | 内容 |
|---|---|
| 模型 | `kimi-k3`（Moonshot 月之暗面） |
| 家族 | Moonshot —— **四个评审家族中的第四个**，与 DeepSeek / OpenAI / Google / Alibaba 均不同源 |
| 端点 | `https://api.moonshot.cn/v1/chat/completions`（OpenAI 兼容） |
| 温度 | 1（模型强制；传 0.3 返回 400） |
| 方式 | 流式（SSE），思考过程与正文分别留存 |
| 规模 | 思考 51,399 字 / 正文 5,452 字 / 53,033 tokens / 604 秒 |

### 为什么单独记一次运行方式

第一次用**非流式**发起，17 分钟零字节返回，无法判断死活。
改流式后真相立刻显现：**它花了约 8.5 分钟纯粹在思考**，正文一字未出。
非流式模式下这段时间在客户端完全不可见。

> 这是运行器实现的缺陷，不是模型故障。已改为流式 + 每 15 秒心跳 +
> 增量落盘，超时也能保住已生成部分。

### 关键核对证据

**阻断 1**（引用全部命中原文）

- 第 2032 行 Q1：「搭建产出的业务系统**独立部署**」（§10.3）
- 第 1330 行：「UI 与 Agent 必须调用**同一个业务命令端点**，由服务端统一执行全部校验」（§9.2）
- 第 1544 行：「任何绕过通道的写入或部署**在技术上不可达**」（§9.6.3）

Kimi 的推理链：§9.2 把唯一执行点放在**业务系统侧**（Agent 不碰数据库），
那么"绕过在技术上不可达"这个强主张要成立，前提是业务系统的服务端运行时
**由平台提供且不可替换**。全文没有这句架构声明 → 该主张目前是**期望**而非**构造性保证**。

这个推理是对的。§5.6（第 936 行）确实写了"搭建产出物是**声明式契约**，不是可执行代码"，
但那是**对搭建者能力的限制**，不是**对部署单元形态的声明**。二者不等价。

**阻断 2**（`审计存储` 一词全文零命中）

但"这个库在哪、归谁、和业务系统库什么拓扑关系"全文无着落。

**重要 5**（`人力` 一词全文只出现在第 145 行）

承认了，但 v2.2→v2.4 三轮修订都没补。Kimi 的"我拒绝签字排期"是有依据的。

**重要 6**（访客）

## 四、一处不精确（必须记录，避免误导后续修订）

Kimi 阻断 1 的第 3 分点称：

> 「§9.4 令牌绑定「授权版本」，但……版本不一致时**如何拒绝，全文无着落**」

**这一句不准确。**第 1448 行 §9.4 明确写了：

> | **授权版本比对** | 业务系统验签后，**将令牌中的授权版本与当前版本比对**；不一致则拒绝 |

所以"如何拒绝"是**有**规定的。

但 Kimi 观察到的底层缺口是**真实的**，只是它混淆了两个不同的概念：

| 概念 | PRD 中的状态 |
|---|---|
| **授权版本**（权限变更后令牌失效） | ✅ 有定义、有比对、有拒绝（§9.4） |
| **契约版本**（Agent 的接口契约客户端与业务系统 schema 版本协商） | ❌ 「契约版本」一词全文**零命中** |

第 1408 行说明「授权版本」的含义是"**权限变更**后旧令牌自动失效"——它是**权限**版本，
不是**契约 schema** 版本。契约演进后 Agent 与业务系统如何协商版本，确实无定义。

**结论**：该分点方向正确、表述不精确，修订时应按"契约版本"而非"授权版本"处理。

## 五、Kimi 明确标注「依赖外部资料，无法核实」的部分

Kimi 主动声明它无法核实以下内容，与前三轮 GPT-5.6 的立场一致：

- `0B-1`~`0B-10`、`0C-1`~`0C-8`、`0D-1`~`0D-8` 任务卡的验收标准与工作量

- 组件注册表白名单内容（`0A-6`）
- `评审/v2.1`~`v2.3/汇总.md` 系列文件

> **这意味着：本 PRD 中所有关于外部系统的事实性声明，至今没有任何一份评审
> 验证过。**这是冻结时必须写明的已知局限。

## 六、本轮结论

> **总体判断（Kimi 原话）**：契约与安全约束已达可实现精度，但部署架构、平台存储、
> 阶段验收三处未闭合——**阶段一可动手，整体不可承诺，尚不可冻结**。

- **可承诺**：阶段一、阶段二
- **不可承诺**：总排期 30-31 周（理由：阶段四五验收标准在外部文档、平台存储拓扑未定、无人力假设）
- **开工前必须补齐**：阻断 1（部署单元与发布架构声明）、阻断 2（存储拓扑基线）、重要 3（资产落库，两句话）
- **承诺排期前必须补齐**：重要 4（阶段验收锚点）、重要 5（人力假设）
