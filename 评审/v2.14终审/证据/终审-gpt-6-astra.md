**未通过——插件生命周期与访客授权仍有产品级缺口，冻结应解除；部分安全承诺仍超出其前提。**

本结论仅依据所贴文本。正文 §0.15 只列出三项保留项，未提供完整的 R1–R5 冻结记录，不能据此确认五项均可接受。

## 阻断（必须修，否则不能开工）

### 1. 插件“注册”的执行效果未定，动态插件又与统一生命周期规则冲突

- **位置**：§0.15、§4.1.1 四、§5.7.1、§9.10.2。
- **原文**：
  - “『注册』动作语义未定义（是否产生运行效果）……列入阶段一验证任务。”
  - “仅当存在激活批准记录时才允许加载。”
  - “加载只发生在进程启动时……不是热加载。”
  - 动态插件“仅进程内存”“跨重启……消失”，且“仅在受控调试场景开启”。
  - 保留理由为：“生产默认禁用，首版影响面为零。”
- **问题**：
  **R2 决定的不是接口命名，而是代码何时获得执行机会。** 如果注册会执行插件代码或注册服务，那么“无激活批准不得加载生效”是否成立尚未确定；如果注册仅写入元数据，则可以成立。两种行为对应不同的安全边界，不能由实现者自行选择。

  **R3 的延期理由不成立。** “默认禁用”不等于“首版不存在开启路径”。正文明确允许受控调试开启动态插件，却未说明这种运行期生效方式如何适用“只在启动时加载”、激活批准及内容指纹规则。现有规则不能直接给出唯一实现。

  已声明的“插件链式注册不受接口约束”是另一项 TCB 例外，不能替代对**产品自身提供的动态插件入口**作出规定。
- **建议**：
  - 现在确定产品规则：注册是否执行代码、是否产生路由或服务，以及它与安装、激活、加载的先后约束。
  - DSH 实际行为可以在阶段一验证，但验证的是**能否满足该规则、需要如何改造**，不能以外部行为代替产品裁决。
  - 对动态插件二选一：首版完全不提供开启路径；或者明确其生命周期例外、批准对象和验收条件。“默认关闭”不足以作为延期依据。
  - 增加明确断言：已安装或已注册但未批准激活的插件，不得产生运行效果；动态入口按裁定后的规则单独验证。

### 2. 访客链接获得了写能力，但签发人授出这项能力的授权依据没有定义

- **位置**：§3.5.1、§3.5.3、§3.1、§9.3。
- **原文**：
  - 链接“由已认证用户（员工或所有者）生成”。
  - “仅能填写并提交被指定的那一张表单。”
  - “提交行为本身即视为对该表单已授予的写权限。”
  - 访客提交“立即成为正式业务数据”。
- **问题**：
  文本定义了链接的真实性、有效期、撤销与限流，却没有定义**签发资格与授予范围**。

  “已认证”只证明账号身份，并不证明该账号有权让外部人员写入指定表单。正文无法回答：
  - 只有读取权限的员工，能否生成该表单的提交链接？
  - 链接允许填写哪些字段，受谁的字段权限约束？
  - 写入属于哪个租户、业务系统及业务归属范围？

  “已授予的写权限”在这里依赖一项未定义的授权。由于提交直接产生正式业务数据，这属于新增写入口的授权缺口，不能仅靠签名技术设计补齐。
- **建议**：
  明确签发链接所需权限，以及链接绑定的公司、业务系统、表单、允许写入的字段和操作范围。签名服务须依据这些规则授权签发，不能仅依据“已登录”。

  至少补充：无签发资格、无表单写权限、越权字段、跨公司或跨系统提交的负向测试；并裁定签发人停用或权限回收后，已有链接如何处理。

## 重要（应修）

### 1. 注入防护仍把“必须确认”写成“不会产生不可逆后果”

- **位置**：§9.7.2、§9.7.3、§9.8.2。
- **原文**：
  - “即使注入成功进入上下文，也无法产生不可逆后果。”
  - “一致性校验……当前用户消息 → 目标对象 → 动作 → 参数……不一致则拒绝。”
  - §9.8.2 又明确：系统不能证明“用户意图与执行动作语义等价”，也不能证明用户理解了确认内容。
- **问题**：
  参数展示与显式确认能够阻断**未经确认的执行**，但用户仍可能确认被注入诱导的错误操作。§9.7.3 的测试证明的是“拒绝或未确认时不执行”，没有证明“注入不会产生不可逆后果”。

  此外，“一致性校验”若指自然语言意图与参数的语义一致，其判定标准仍未定义；若仅指引用、对象和凭证的结构一致，应明确写出。不能把前者当作已有机器保证。
- **建议**：
  将承诺收窄为“不可逆动作未经有效确认或规定审批不得执行”；明确已确认错误操作的残留风险。

  将一致性校验拆成可确定判定的绑定检查与语义辅助检查，后者不得作为安全保证。技术设计还应落实并测试：服务端如何可信地区分 UI 与 Agent 调用，避免 §9.6.1 的额外防护仅靠调用方自报通道。

### 2. 在线“立即撤销”与允许使用缓存之间仍缺少优先规则

- **位置**：§3.5.1、§4.6.4、§9.4.2、§9.4.4。
- **原文**：
  - “账号停用或会话结束时，旧令牌必须立即失效。”
  - 访客链接吊销后“立即失效”。
  - 链接验证可以“每次……查询，或采用带短 TTL 的缓存”。
  - “短时有效期只能作为故障时的残留窗口。”
- **问题**：
  在平台正常在线时，如果业务系统刚缓存了“未撤销”，随后发生停用或吊销，下一次请求继续使用有效缓存，仍可能放行。

  文本只明确接受了**平台不可用时**的残留窗口，却没有规定如何避免上述**在线缓存窗口**。因此“立即失效”尚不能由现有规则推出。
- **建议**：
  明确在线撤销的产品时效要求，以及在线验证与缓存使用的优先关系。若仅允许故障期间使用旧状态，应明确这一限制。

  验收分别覆盖“平台在线、缓存未过期时撤销”与“平台离线时撤销”，不能只测后者。

### 3. 契约可以回滚，不代表已有业务数据能按旧契约继续运行

- **位置**：§5.1、§7.4.1、§7.4.4、§9.4.3。
- **原文**：
  - 搭建能力包含修改数据模型。
  - “回滚 = 新增一个发布，其契约内容与某个历史版本相同。”
  - 首版“没有备份恢复能力”“不迁移历史数据”。
- **问题**：
  契约版本号的回滚语义已闭合，但**已有数据与新旧契约的兼容规则未闭合**。

  例如，某字段由 `integer` 改为 `short_text` 后写入非数字内容，再发布旧整数契约：版本号完全合规，现存数据却未必可解释。正文没有裁定首版是否允许此类已上线结构变更，也没有规定不兼容回滚应拒绝。

  这不是要求首版增加迁移功能，而是要明确**没有迁移与恢复能力时允许哪些修改**。
- **建议**：
  给出首版已上线系统的变更边界；不受支持的数据转换、破坏性变更和不兼容回滚应明确拒绝。验收须使用已有业务数据，不能只比较契约内容与版本号。

### 4. R3 的“跨数据范围操作”与不可豁免的基础授权关系不清

- **位置**：§9.3、§9.6.1、§9.6.4.1。
- **原文**：
  - 写入必须按“目标 ID ＋ 当前租户 ＋ 当前数据范围”定位，“零行命中统一返回 404”。
  - 确认与审批属于基础校验之上的“额外防护”。
  - R3 包含“跨数据范围操作”，处置为“须所有者审批”。
- **问题**：
  如果“跨数据范围”指超出执行账号的授权范围，基础校验就必须拒绝，所有者批准不能单独使其成功；如果指授权范围内跨多个业务分组，则应换成明确的业务定义。

  当前文本不能唯一判定“员工访问范围外记录、所有者已批准”这个测试应如何结束。
- **建议**：
  明确审批不替代基础授权；定义 R3 此处究竟指哪种跨范围动作。若需要先调整权限，则应走既有授权流程，再按更新后的身份执行。

### 5. 插件冒用窗口不能严格写成会话存活期与插件驻留期的较小值

- **位置**：§9.4.1、§9.4.2。
- **原文**：
  - “实际冒用窗口 = min(会话存活期, 插件驻留期)。”
  - 插件可取得真实的短时令牌；单令牌有效期“≤ 5 分钟”。
- **问题**：
  移除插件并不等于撤销它已经取得的令牌。插件在移除前取得并传出的令牌，仍可能在移除后、到期前被使用；正文没有定义“插件卸载即撤销相关令牌”的机制。

  因而这里把“停止持续取得新令牌”当成了“既有令牌立即失去效力”。会话结束还存在文档已接受的离线撤销窗口。
- **建议**：
  删除该严格等式。分别说明持续取令牌的窗口、已取得令牌的剩余有效期及撤销传播窗口，不承诺卸载即终止全部冒用。

### 6. 验收锚点没有完整承接正文要求，不能宣称逐项闭合

- **位置**：§4.6.3、§7.1、§9.4.1。
- **原文**：
  - 双引擎一致性“列入阶段一验收锚点”。
  - 阶段一实际列出的验证器条件是 Node 跑通结构测试、Schema 指纹一致，没有双引擎一致性条件。
  - §7.1 又规定锚点是“验收条件本体”，与任务卡不一致时“以本表为准”。
- **问题**：
  **Node 测试通过、Schema 指纹相同，并不能证明 Python 与 Node 判定一致。** 此处是具体的验收承接遗漏。

  另外，§9.4.1 保留了历史上的“非当前会话主体”测试，同时给出修正后的“无活跃认证会话主体”测试；阶段五要求该节“全部负向测试”通过。历史说明与当前验收要求需要明确区分。
- **建议**：
  在阶段一补入双引擎一致性门禁；给当前有效负向测试建立唯一清单，并明确历史测试不参与验收。无需为此重写全部修订史。
