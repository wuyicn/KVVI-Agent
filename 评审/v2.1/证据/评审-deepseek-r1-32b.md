

## 总体判断

文档整体结构清晰，内容详尽，但在某些方面存在逻辑不一致和潜在风险。

---

## 阻断（必须修，否则不能开工）

### 1. **红线与实际设计的不一致**
- **位置**：§9.1 红线总表与 §2.5 权限与状态机
- **原文**：§9.1 红线 1 要求 Agent 必须走与系统 UI 完全相同的校验，而 §2.5 提到工作模式 Agent 不新造权限，继承搭建产出物。
- **问题**：实际设计中，工作模式 Agent 的权限继承可能无法完全覆盖所有 UI 校验，存在潜在越权风险。
- **建议**：在 §2.5 中明确 Agent 如何强制执行 UI 校验，确保与红线 1 一致。

### 2. **金额类型的未统一**
- **位置**：§5.4 金额约定与 §5.5 字段类型
- **原文**：§5.4 废除“整数分”约定，采用 `money` 类型，而 §5.5 列出的字段类型中未明确包含 `money`。
- **问题**：字段类型未明确包含 `money`，可能导致实际实现中仍使用旧类型。
- **建议**：在 §5.5 中明确 `money` 为字段类型之一，并删除旧的“整数分”相关描述。

## 重要（应修，影响成功率或成本）

### 1. **部署形态与身份层的依赖**
- **位置**：§4.4 部署形态与 §3.2 身份与凭据
- **原文**：§4.4 提到本地化部署与云服务部署，而 §3.2 强调身份层必须自有无依赖。
- **问题**：本地化部署可能面临身份层实现的复杂性，影响部署成本和时间。
- **建议**：在 §3.2 中详细说明身份层在本地化部署中的实现方案，确保与部署形态一致。

### 2. **离职交接的单据状态处理**
- **位置**：§3.3 账号生命周期与离职交接
- **原文**：提到在途单据必须显式交接，但未明确如何处理未提交的单据。
- **问题**：未提交的单据可能成为孤儿数据，影响系统稳定性。
- **建议**：在 §3.3 中明确未提交单据的处理流程，例如自动归档或通知继任者。
