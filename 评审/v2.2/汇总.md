## 三、安全设计审查（§9 独立审查）发现

**总体判断（原文）**：

> §9 原则方向基本正确，但 **A1、A2、A5、A7 的「修复」多停留在声明层面，
> 缺乏强制机制与实现规范**，若干攻击路径仍可存活。

### 阻断级

| # | 问题 | 核心 |
|---|---|---|
| **S1** | **A1 第一层在技术上不可实现** | LLM 上下文只是一串 token，**不存在「指令区」与「数据区」的结构化隔离**；「工具调用只由当前用户消息触发」在模型生成层无法强制。且「全局禁止开关」未限定操作者，**被注入诱导关闭则第一层整体消失** |
| **S2** | **A7「可证意图」的判定不成立** | 会话与消息引用只能证明「这句话出现过」，**不能证明语义映射的等价性**；「模型如何理解」是不可审计的黑箱。§9.8.2 的「已由既有链路覆盖」**结论不成立** |
| **S3** | **A2 仍可绕过：缺「发布路径唯一性」** | PRD 从未定义「发布」，未规定发布是权限生效的**唯一技术通道**；搭建者可直接改存储或调部署 API。且**新建系统**的初始权限未纳入审批——**搭建者可通过「新建」而非「修改」绕开** |
| **S4** | **A5 无法落地：密钥管理完全未定义** | 业务系统独立部署、身份层自建，**信任锚点、密钥分发与轮换均未定义**。且 §9.1 的地基清单**不含密钥管理** |

### 重要级

| # | 问题 |
|---|---|
| S5 | **A6 前置约束无强制机制**——纸面约束，差异报告不校验该不变量；含「汇总可见个体不可见」的配置仍可被发布 |
| S6 | **§9.6 高风险清单过宽，与红线 1 冲突**——若 Agent 的审批要所有者批而 UI 不用，则违背「同一套校验」；若统一批，则日常审批被阻断、产品不可用 |
| S7 | **搭建者可自我配置业务权限**——§3.1 允许搭建者配业务权限，但未禁止他把**自己**纳入高数据范围 |
| S8 | **§9 完全缺失**：模型服务商数据流出、拒绝服务与配额、运维面（密钥/配置/日志）安全 |
| S9 | **历史消息定位不清**——它既非「数据区文本」也非「当前用户消息」，§9.7.3 的测试与 §9.7.1 的防护错位 |

### 建议级

- S10 §9.9.2「引用携带租户」与 §9.4「模型不得控制 tenant」**表述矛盾**——若 `target_ref` 由模型生成且含租户，模型事实上就控制了它
- S11 审计日志防篡改机制需具体（追加写 + 哈希链 / WORM），且读权限须独立于搭建权限
- S12 **地基违规检测未定义**——没有机制检查搭建是否试图修改地基

### 红队清单（§9 仍未覆盖，按严重度）

1. 通过**新建系统**直接植入宽泛权限（绕过 A2 审批）
2. 通过**直接修改 MetaSchema 存储**绕过发布审批
3. **历史消息中注入指令**诱导高权限用户
4. 诱导 Agent 批量查询/批量创建导致**资源耗尽**
5. **云模型 API 数据流出**（业务数据无脱敏发往外部）
6. **审计日志被篡改**（无防篡改要求，操作者可删改）
7. 搭建者**配置自己的业务数据访问权限**
8. 聚合差分在「汇总可见个体不可见」配置下**复活**
9. **令牌密钥泄漏**导致委派身份被伪造

## 四、两份评审共同指出的模式

**两份评审独立指出了同一类问题：§9 的若干要求停留在「声明」而非「机制」。**

| 声明式写法 | 评审要求补上的机制 |
|---|---|
| 「指令与数据结构化隔离」 | 具体的编码/转义/双通道格式 |
| 「审批后方可发布」 | **发布是唯一技术通道**且绕不过 |
| 「业务系统验证签名」 | 信任锚点、密钥分发与轮换 |
| 「不得产生汇总/个体权限切分」 | 机器可执行的不变量检查 |
| 「审计可追溯全链路」 | 承认证明力边界，或改为操作确认 |

**这不是措辞问题，是「写了但要实现时无路可走」的问题。**

### 类别 B：需要补设计（有明确方向，可写）

| 项 | 补什么 |
|---|---|
| L5 | 会话创建时**同时绑定业务系统** |
| L6 | 草稿的**业务归属接管人**与**流程继任者**分开处理 |
| L9 | 令牌失效的执行规则（在线校验或撤销列表） |
| S3 | **发布唯一通道** + 新建系统纳入审批 |
| S4 | **密钥管理纳入地基** + 信任锚点与轮换 |
| S7 | 禁止搭建者配置自己的业务权限 |
| S8 | 新增「运行与运维安全」一节 |
| S9 | 明确所有非当前用户消息的上下文按不可信数据处理 |
| S10 | 明确**租户标识不出现在模型参数中**，由服务端覆盖校验 |
| S11 | 审计日志防篡改与独立读权限 |
| S12 | 地基不变量检查纳入产出物验证管道 |

### 类别 C：需要用户决策（涉及产品取舍）

| 项 | 待定 |
|---|---|
| **S1** | A1 第一层怎么做：**删除**（只留第二层）？还是**改写为可落地的机制**（数据安全编码 + 工具调用执行前服务端验证触发来源）？「全局禁止开关」是否保留、谁能关 |
| **S2** | A7 定位：#1 明确声明「**KVVI 不承诺意图证明**」，风险前移到**操作确认**（执行前展示结构化参数并要求显式确认）；#2 记录模型映射结果并声明证明力边界 |
| **S6** | §9.6 清单边界：区分**基础校验**（UI 与 Agent 一致）与**额外注入防护**（仅对 Agent 加确认），并收窄清单 |
