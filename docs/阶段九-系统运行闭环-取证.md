## 验收结论

判据是「一个新系统可从自然语言需求走到发布，并由员工打开和提交第一条真实记录」。
检查器把它拆成四类证据，每一类各自回答判据的一半，缺一不可 —— 少任何一类都可能
出现「其余全绿而闭环是断的」。

| 证据层 | 可重跑证据 | 已证明的边界 |
|---|---|---|
| 契约完备 | `contracts.test.mjs`、`runtime-projection.test.mjs` | 六份契约缺一份就**跑不起来**，且报得出缺哪几份；视图引用的字段必须在模型里声明；迁移端点必须在状态表里 |
| 运行时接口 | `api-router.test.mjs`、`system-api.test.mjs` | 身份**只**从已验证会话导出；请求体里的 `companyId` 递归剥除；只读员工改记录 → 403 且**逐字段不变**；陈旧 `rowVersion` → 409 且**不覆盖**新记录；404 与 403 语义分开 |
| 客户端渲染 | `runtime-ui.spec.tsx`、`record-views.spec.tsx`、`system-shell.spec.tsx` | 契约里的组件名只认一张**显式导入**的闭合表（23 个名字）；表外组件、用错视图类型、缺字段绑定一律**阻断且什么都不画**；`HIDDEN` 不渲染**也不提交**；`MASKED` 不进 payload |
| 端到端回路 | `publish-runtime-e2e.test.mjs` | 现场**新建**一个系统 → 发布 → 员工拿投影 → 提交第一条记录（201 + 记录号）→ 从列表端点**重新读回** → 改一次版本递增、未改字段仍在 |

检查器另有一个反退化约束：每个证据类除了 `exit 0`，还要求**实际通过的条数不低于下限**
（契约 12 / 接口 12 / 渲染 30 / 端到端 7）。只判退出码时，一个把测试删光的提交同样绿 ——
而绿得毫无意义。`skipped` 一律算失败。

| 模块 | 位置 | 作用 |
|---|---|---|
| 产品 API 路由 | `services/platform/src/api-router.mjs` | 平台先认领 `/api/v1/`（比运行时的 `/api` 更具体），鉴权只认会话 |

| 闭合渲染器 | `forks/dsh/变更/packages/client/kvvi-panel/src/client/` | 契约是数据不是代码；组件表之外一律阻断 |

## 取证过程抓到的两个缺陷

端到端测试的价值在于它是**从外面**走的。它在这条路上抓到两个此前全绿的缺陷：

1. **「缺哪几份契约」在响应里消失了。** 投影抛出的 `detail` 是结构化的
   （`{assetId, missing}`），而 API 把它塞进了一个 `detail` 字段 —— 于是状态码与错误码都对，
   补的人却看不到该补哪一份。判据里「逐份报出缺了哪些」这句话根本没落地。
   修法：在 `systemRuntime` 把投影的 `detail` **摊平到顶层**。
2. **创建记录不回 `rowVersion`。** `POST /records` 返回 201 与记录号，但没有版本号，
   于是创建者要改自己刚建的记录就必须**再读一次**才敢写 —— 而读与写之间正是丢更新的窗口。
   修法：`createRecord` 的 `RETURNING` 带上 `row_version`。

两者都不是「测试写错了」：断言描述的是产品应有的行为，实现没做到。

## 本阶段没有主张的内容

G7 只关闭「契约齐备的系统能不能被员工打开、填单、读回」。它不代表以下内容已经完成：

- 发布视图里的 `Table`（`DataBindingRef` → `queryCode`）**跑不起来**：平台没有查询端点，
  客户端明确阻断为 `KVVI_TABLE_QUERY_UNSUPPORTED`，而不是画一张空表。面板的「记录」半页
  是当前可用的替代（数据来自 `/records`）；
- **流程动作按钮未做**：投影带得到 workflow 状态与迁移，详情页也显示了当前状态的中文名，
  但没有「提交 / 通过 / 驳回」按钮 —— 平台没有迁移端点，放一个按不动的按钮比不放更坏；
- **生产组件注册表仍是黄金样例夹具**（N11）：客户端那张闭合表是与
  `样例/黄金样例/*/context.json` **手工对齐**的，不是从注册表资产加载的；
- 「自然语言需求 → 契约」这一段由搭建引擎模式（阶段八 preset）承担，
  G7 验的是**从契约到第一条记录**的后半段；
- 所有者还没有员工、角色和权限管理界面（阶段十 / G8）；
- 私有化安装、升级、备份、恢复、回滚尚未完成异机验收（阶段十一 / G9）；
- 离线签名 Skill / Plugin 包还不能安装、启用和回滚（阶段十二 / G10）。

因此，「G7 已完成」不能表述为「产品闭环或发行版已经全部完成」。
