# `0D-1` AI 蓝图闭环

> **阶段三锚点④ 的取证。** 判据可重跑：
>
> ```bash
> python3 工具/check_blueprint.py 样例/蓝图/通用事项管理系统
> bash 工具/check_blueprint_自测.sh          # 反向测试 13/13
> python3 工具/蓝图样例.py --check            # 样例与生成结果一致
> ```

## 一、判据来自哪里

`0D-1` 的验收原文（KVVI-Builder `docs/progress.json`）：

> **说人话 → 蓝图 → 类型化命令 → DraftGraph → 校验/影响/预览 → 你点通过**

本检查器把六个阶段**逐段变成可判定的**。任何一段不成立，闭环就没有闭合 ——
不是「大部分跑通」。

## 二、六段分别查什么、依据是什么

| 阶段 | 查什么 | 依据 |
|---|---|---|
| ① 说人话 | `00-需求.md` 存在、不空洞、**含「待确认的问题」**；每份产出物的中文名都能在需求里**找到依据** | 本检查器（可追溯性） |
| ② 蓝图 | 合法（`kvvi-blueprint/v1`）；**五部分齐全**（数据模型 / 表单 / 流程 / 看板 / 接口） | PRD 行 1363：可运行业务系统的全套定义 |
| ③ 类型化命令 | 35 条命令逐条过 `app-model-command/v1alpha1`（**结构**）；同草稿；`draft.compile` 恰好一次；`draft.submitForApproval` 收尾 | 契约 |
| ④ DraftGraph | **确定性重放**：`base_revision` 连续；目标必须由**更早**的命令创建（拓扑序）；**命令建出的节点序列与产出物逐位一致** | 本检查器（见 §四） |
| ⑤ 校验 / 影响 / 预览 | 每份产出物过契约校验（能完整走完整走）；口径过 §9.8.1 不变量；影响报告**摘要与产出物一致**；预览**可由产出物重算出来** | 契约 + 本检查器 |
| ⑥ 你点通过 | 审批记录存在、过 `approval-attestation/v1alpha1`、**绑定同一份 DraftGraph 摘要**、`decision=APPROVE` | 契约 + 本检查器 |

**实际结果：六段全部成立，闭环闭合。** 命令 35 条、11 种类型；
蓝图提供的外壳 4 个；表单 10 个节点、看板 7 个节点，命令序列与产出物逐位一致。

## 三、为什么第 ④ ⑥ 两段必须自己查

结构校验器**自己写明了不覆盖**这些。`contracts/meta-schemas/0a-full-r1/README.md`
的「验证边界」一节：

> | Command/Tool | **幂等历史、`base_revision`**、稳定节点/风险升级、
>   组件属性和字段参数与实际登记关联 |
> | 全部引用 | 精确注册资产存在性……**不可变版本/正文摘要**…… |
> | 发布四对象 | 跨对象摘要/身份相等……**有效人工审批**…… |

本检查器补的正是这几项：**`base_revision` 连续性、拓扑序、正文摘要重算、
影响报告的新鲜度、审批与摘要的绑定**。

> **结构校验通过 ≠ 闭环闭合。** 两者都要有，缺一个都不算。

## 四、本项目自己定义的口径（契约里没有）

| 量 | 定义 | 为什么必须有 |
|---|---|---|
| **DraftGraph 摘要** | `c14n(按 (part, code) 排序的资产清单)` | 审批要绑定「被出示的那一份」。哪一份？没有摘要就绑定不了 |
| **预览** | 由 `view-schema` 节点树渲染（`工具/lib/蓝图.py::render_preview`），逐字节可复现 | 预览如果是手写的，它就不是预览 |

定义只有一处（`工具/lib/蓝图.py`），**生成器与检查器共用** ——
两边各写一套必然漂移，然后检查器会用另一套规则去查生成器的产出，报一堆假问题。

## 五、闭环检查暴露的第一个真问题：五份产出互不相干

这是本次阶段三**最重要的发现**，而它是逐份校验**永远看不出**的。

| 来源 | `general_item` 的字段 | 摘要 |
|---|---|---|
| `样例/business-schema/通用事项.spec.json`（`data-model` 的产出） | `item_no` / `title` / `detail` / `amount` / `due_date` / `item_status` | `898c0ae1…` |
| `样例/view-schema/context.json` 内嵌的那份（**旧**） | `title` / `category` / `quantity` / `amount` / `due_date` / `notes` | `518077ba…` |

两边**各自都过完整校验**，但表单绑定的 `category` / `quantity` / `notes`
在真正的模型里**根本不存在**。

> **「五份产出逐份通过校验」与「五份产出构成一个系统」是两件事。**
> 前者靠 `工具/check_skill_output.py`，后者只有把五份装在一起才看得出来。

**已修**：`工具/视图样例上下文.py` 由数据模型样例重建两份上下文，
表单改绑真实字段，看板改绑真实模型摘要，两份 `SKILL.md` 的内嵌示例同步重嵌并复验。

同一族的第二处：字段类型注册表在业务侧叫 `fake-business-types`、
视图侧叫 `business-field-types-core`，**摘要相同、`asset_id` 不同**，
而引用校验按 `asset_id` 找 —— 于是找不到。已统一。

## 六、本闭环**未覆盖**什么（必须与「通过」一起读）

| # | 未覆盖 | 说明 |
|---|---|---|
| 1 | **接口（`tool-spec`）不由命令产出** | 14 个命令里没有任何一个产出 `tool-spec`。接口部分只做到「契约校验 + 摘要一致」，**没有命令级溯源**。检查器每次都会把这条报出来 |
| 2 | **撤销重做未验证** | `draft.undoCommand` / `draft.redoCommand` 未在样例出现，幂等历史未验证 |
| 3 | **批准之后不在闭环内** | 本闭环到「你点通过」为止；注册、上线、环境晋级不在其中 |
| 4 | **判定的是配置，不是运行期** | 运行期是否真按配置执行，是另一件事 |
| 5 | **「说人话 → 蓝图」这一步没有模型参与** | 检查器验证的是**蓝图与产出的自洽**；`00-需求.md` → `蓝图.json` 的转换是五个 Skill（锚点①）的职责，本检查器不调用模型 |

> 第 5 条尤其要说清楚：**本闭环证明的是「闭环机械上是闭的」**，
> 不是「AI 能自动写出正确的蓝图」。后者由锚点①（五个 Skill）与
> `0D-2`（黄金样例）承担。

## 七、反向测试（证明它不恒绿）

`工具/check_blueprint_自测.sh` **13/13 通过**。逐项把闭环弄坏，要求它变红：

| 破坏方式 | 结果 |
|---|---|
| 缺 `审批.json` | ❌ 红 |
| 审批结果是 `REJECT` | ❌ 红 |
| 审批绑定到别的摘要（批的不是这一份） | ❌ 红 |
| `base_revision` 跳版本 | ❌ 红 |
| 目标节点在更晚的命令里才创建（拓扑序反了） | ❌ 红 |
| 影响报告与产出物摘要不符（**陈旧报告**） | ❌ 红 |
| 预览被手改（不是推导出来的） | ❌ 红 |
| 表单绑定了模型里不存在的字段 | ❌ 红 |
| 删掉 `draft.compile` | ❌ 红 |
| 蓝图缺「接口」这一部分 | ❌ 红 |
| 产出物没有命令溯源、也没说明原因 | ❌ 红 |
| 指向一个不是蓝图的目录 | 退出码 **2**（无法执行，不是通过） |

## 八、跟产物放在哪

```
样例/蓝图/通用事项管理系统/
├── 00-需求.md                      说人话：业务原话 + 待确认的问题
├── 蓝图.json                       蓝图 + id 表 + 产出物清单（含命令溯源）
├── 命令/*.command.json             35 条类型化命令（app-model-command/v1alpha1）
├── 影响.json                       ImpactReport（evidence-bundle/v1alpha1）
├── 预览/*.html                     由 view-schema 节点树渲染，逐字节可复现
└── 审批.json                       「你点通过」（approval-attestation/v1alpha1）
```

产出物本身（`business-schema` / `view-schema` / `workflow-spec` / `tool-spec`）
**不复制进蓝图** —— 蓝图**引用**它们。一份产出只有一个家。
