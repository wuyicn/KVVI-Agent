## 一、判据来自哪里

`0A-14` 的验收原文（KVVI-Builder `docs/progress.json`）：

> **代码里没有「报货单」这类家具词。**

PRD §7.1 把它列为阶段三锚点②；§5.7.3 与 §9.1 给出理由：
**行业扩展包按需叠加，地基无需改动**。所以「没有行业词」不是洁癖 ——
地基里出现某个行业的词，说明某一行业的假设已经渗进了本该中立的层。

## 二、扫什么、不扫什么

| | 范围 | 为什么 |
|---|---|---|
| ✅ **扫** | `contracts/`、`protocol/`、`tools/`、`tests/`、`services/`、`scripts/`、`样例/`，以及 **fork 里登记过的 35 个改动文件** | 这些是产品本体 |
| ❌ **不扫** | `docs/`、`评审/`、`冻结/`、`进度.md`、PRD | 过程文档**必须**引用 PRD 原文，而 PRD 的锚点① 就写着「家具『报货申请』样例」。扫它们只会得到与产品无关的命中 |

> **fork 只扫「登记过的改动文件」**：`vendor/dsh` 的主体是上游代码，
> 上游是否出现行业词不归我们管。用 `forks/dsh/改造点指纹.json` 的文件清单，
> 恰好圈出**我们写的那些**。

**实际扫描面：1383 个文件；词表 40 个词，覆盖 8 个行业。**

## 三、两个方向都要查

只查「没有行业词」是半个判据 —— 一个把 `skills/` 写死的实现同样「没有行业词」，
但它**长不出任何行业**。所以本检查同时要求：

| 方向 | 要求 | 结果 |
|---|---|---|
| **负向** | 扫描面内没有行业词 | ✅ **0 处违规** |
| **正向** | 行业扩展点存在且可用 | ✅ 预设的 Skill 目录是 `customSkillDirs` **可追加列表**，行业包以「多一个目录」接入（PRD §5.7.3） |

## 四、查出来的东西（都改掉了）

### 4.1 词表错误：`BOM`

我最初把 `BOM` 收进「制造」行业词。实测 6 处命中，**全部是假阳性** ——
在 JSON 世界里 `BOM` 指 **Byte Order Mark**（`bundle-policy.mjs` 的
`ignoreBOM: true`、c14n 的 UTF-8 BOM 向量）。

**教训记在词表注释里**：宁可少收也不用会误报的词 ——
**误报会让整套检查被当成噪声而绕过**。

### 4.2 `kvvi-worker` 预设里的家具示例（3 处，已中立化）

工作模式的人格把家具场景当**旗舰例子**：

| 位置 | 原文 | 改成 |
|---|---|---|
| 文件头注释 | 「报货」「这单发货了吗」 | 「这单到哪一步了」「我这个月做了多少」 |
| 人格「用户用自己的话」 | 「报货」…「我提成多少」「看下自己销售」 | 「这单到哪一步了」…「谁审的这一单」「把这张单撤了」 |
| 流程语义例子 | *报货 is the ordinary case… 撤单重建… 申请撤单* | *withdrawing and resubmitting… 撤回后重提… 正式撤销申请* |

**为什么改而不是豁免**：搭建引擎的人格**明令禁止**这些词
（*「Do not reach for 「报货单」…」*），而工作模式却把它们当例子 ——
这个自相矛盾正是 `0A-14` 该抓的东西。语义（正常撤回重提 vs 需审批的正式撤销）
一字未动，只去掉行业名词。

> ⚠️ 这是**模型可见文本**的改动。改后未做快照回归（本仓库不跑 DSH 的测试套件），
> 列入交付前待办。

### 4.3 禁止性提及（7 处，显式豁免，逐条带理由）

劝人不要用这些词的文件，必须能叫出被禁止的名字：

| 文件 | 词 | 理由 |
|---|---|---|
| `kvvi-builder/agent.cordis.yml:63` | 报货单 / 报货 / 病历 | 人格明令禁止 |
| `skills/data-model/SKILL.md:44` | 报货单 / 报货 / 家具 / 病历 | Skill 明令禁止把行业词当原语 |

**豁免不是万能钥匙**：理由必填（空理由判为**配置错误**，不是通过），
且每条豁免必须至少命中一处 —— **过期豁免会被报出来**（与 G2 的登记项同一套纪律）。

### 4.4 刻意的取舍（不收录的词）

| 词 | 为什么不收 |
|---|---|
| 审批 / 状态机 / 权限 / 数据范围 | 平台通用词，被契约正当使用 |
| 门店 / 客户 / 订单 / 库存 | 跨行业通用，不是某一行业的「家具」 |
| 安装 / 送货 | 软件安装、通用物流都会用，命中会有假阳性 |
| 工单 | 制造与售后通用，不足以断言行业 |

## 五、防「恒绿的检查」

`0A-14` 这类检查最容易退化成三类恒真，三种都表现为「跑得通、报通过」：

| 退化方式 | 防护 |
|---|---|
| 扫描面塌了（没扫到文件） | 文件数低于下限 `MIN_FILES=400` → 退出码 **2**（不是通过） |
| 词表空了（没词可命中） | 词表规模被打印；为空 → 退出码 **2** |
| 路径写错（永远 0 命中） | 反向测试往扫描面注入「报货单」→ **必须变红** |

`工具/check_industry_neutral_自测.sh` **8/8 通过**：

```
[1] 真实扫描面 → 通过，且负向/正向判据都给出结论
[2] 词表 40 个词（≥20）
[3] 注入「报货单」→ 红
[4] 撤掉探针 → 通过
[5] 扫不到文件 → 退出码 2（不是绿灯）
[6] 空理由的豁免被拒
```

## 六、本报告不主张什么

- **不主张「没有任何行业痕迹」** —— 主张的是「在**声明的扫描面**内、
  用**声明的词表**，0 处违规」。扫描面与词表都写在检查器里，可被审阅与挑战。
- **不主张词表完备** —— 40 个词覆盖 8 个行业，是**可执行的起点**，不是穷举。
  新行业词应当随手补进 `LEXICON`，补的时候**先跑一遍看会不会误报**。
- **不主张产物中立就等于**员工看到的东西中立 —— 那由 Skill 的产出决定，
  属于 `0D-2`（黄金样例）的范围。
