## 验收结论

判据是「同一账号、同一动作、同一数据范围下，UI 与 Agent 的允许/拒绝与结果一致」。
检查器把判据拆成六类证据，另加两项跨进程检查。

| 证据层 | 可重跑证据 | 已证明的边界 |
|---|---|---|
| 管理 API | `admin-api.test.mjs`、`admin.test.mjs`、`permissions.test.mjs`、`lifecycle.test.mjs` | 所有者 / 被委托者 / 员工三层各自的能力边界；建账号与加成员同事务（重名不留孤儿）；策略整体替换；停用立刻结束全部会话；§9.6.7 自授权禁令接到新入口；最后一个所有者不可移除 |
| 管理界面 | `admin-ui.spec.tsx` | 员工看不到管理内容**但接口各自判定**；被拒时显示服务端的码而非乐观成功；停用是两步；数据范围是多选；平台保留角色不提供业务策略编辑；保存发的是完整列表 |
| Worker 工具 | `tools.spec.ts` | 身份只来自 `ctx.kvviModeRouter.requireMode()`；身份字段在**执行前**递归拦下；平台拒绝码原样上报；工具集里没有任何搭建设施 |
| 差异等价 | `ui-agent-e2e.test.mjs`、`api-router.test.mjs` | 七个向量上两条通道的判定逐字段相同（见下） |
| 签名一致 | `check_signed_context` | 工具签出的上下文交给**平台自己的**验签函数；改一个字节即被拒 |
| 预置构成 | `check_worker_composition` | `kvvi-worker` 有业务工具、没有任何搭建设施（两个网关分离的落地处） |

差异等价的两个通道是：

- **UI 通道** = `/api/v1/systems/...`，凭据是 worker 的**会话令牌**
- **Agent 通道** = 同一个路由，凭据是工具**实际会发的**签名运行时会话上下文

七个向量：允许的创建、HIDDEN 字段、READONLY 字段、缺 create 权限、
可执行动作清单与非法迁移、陈旧 `rowVersion`、账号停用。另有三条负向：
头里换一个人、网关不一致、签名不符。

## 取证过程抓到的缺陷

端到端与差异测试的价值在于它们**从外面**走。这一轮抓到五处此前全绿的缺陷：

1. **`policies` / `role_members` 没有 DELETE 授权。** `migrate.mjs` 的注释还写着
   「`rate_events` 是唯一需要 DELETE 的表」。整体替换策略撞上
   `permission denied for table policies` —— 看起来像业务错误，实际是权限清单漏了表。
2. **投影把契约里的 `states` 数组折成了对象**，而流程运行时 `workflow.mjs` 按数组读。
   一处事实两个形状，接流程端点时 `spec.states.map is not a function`。
   派生查表改名 `stateLabels`，契约形状原样保留。
3. **新增的两处投影失败处理丢掉了 `detail`。** `systemRuntime` 已经修过一次
   （「缺哪几份契约」到不了界面），新写的流程端点又各自写了一遍简化版，
   于是理由再次消失。三处合并成一份 `projectionFailure`。
4. **`shipped-root.spec.ts` 从阶段八起一直是红的。** 它把预置清单写死成上游四个，
   而 KVVI 多了两个；`pnpm run test:gui` 不跑预置包，所以没人发现。
5. **四处 KVVI 自己的文档门禁红**：硬折行、`kvvi-panel` 没有任何依赖段、
   五个包没写「为什么不发布 invariant」、`kvvi-brand` 与 `kvvi-mode-router` 没有 README。

另有三处是**我写测试时的错误**，记下来因为它们都会让人误判被测代码：

- 差异测试的写向量**两条通道共用了同一条记录**：同一 `rowVersion` 写两次，
  第二次必然 409 —— 看起来像 Agent 通道坏了，其实是夹具让它们排队。
  改成每条通道各建一条（且标题不同，否则读回时 `find` 会挑到对方那条）。
- 夹具改策略后**没有重建会话**：改策略会抬高授权版本、令旧令牌失效，
  于是后续每个向量都拿到 401。**夹具的副作用要自己收尾。**
- 建系统时用同一个账号**既提交又审批**：撞上 §9.6.1 自审批禁令，
  而 `approveDraft` / `publishDraft` 拒绝时**返回对象而不抛异常**，
  于是发布静默没发生，症状出现在很远处（`/actions` 报 `system-not-found`）。
  现在每一步都断言返回值。

## 本阶段没有主张的内容

G8 只关闭「两条通道在同一账号、同一动作、同一数据范围下判定一致」。它不代表：

- **委托范围只有一种粒度**：本仓库里的委托机制就是平台保留角色 `admin`，
  没有「只管某个部门」这种更细的委托 —— 策略模型里没有承载它的字段，
  凭空加一层会让「谁管谁」出现第二份判据；
- **`aggregate_read` 未注册**：平台没有聚合端点，§9.8.1 还要求
  「看得见汇总的人必须看得见每一条构成」，注册一个永远失败的工具有害无益；
- **READONLY 字段的写入路径尚未逐字段拒绝**：当前执法点是字段可见性。
  G8 证的是两条通道给**同样的可写性判定**，不是「写入被拒」；
- **详情页还没有流程动作按钮**：端点已就位、Worker Agent 已能用，
  但界面上还点不了；员工目前只能通过对话推进流程；
- **员工端没有独立的待办视图**：待办口径仍需要平台侧一个聚合端点；
- **所有者管理界面没有分页**：成员与角色列表一次全取。

因此，「G8 已完成」不能表述为「员工与管理闭环已经全部完成」，
更不能表述为「私有化发行版或离线扩展生态已经完成」（阶段十一 / G9、阶段十二 / G10）。
