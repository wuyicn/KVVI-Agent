# KVVI-Agent 项目介绍

> 面向程序员/协作者的项目说明。回答三个问题：**基于什么、做什么、要达到什么目标。**

## 一句话

KVVI 是一个基于 DeepSeek Harness（DSH）构建的**智能生成式应用搭建平台**——搭建者用自然语言描述业务需求，AI 自动生成一套完整的业务系统（表单、审批流、看板、接口），发布之后，普通员工在同一套界面里用自然语言查数据、办业务。

---

## 一、基于什么（技术底座）

KVVI 建立在 **DSH（DeepSeek Harness，`github.com/deepseek-ai/deepseek-harness`）** 之上，是它的一个 fork。DSH 是一个「全插件」的 Cordis agent 运行框架——agent 循环、会话、工具、模型调用、Web 界面都由插件提供。KVVI 在这个底座上加了**一套自己的业务层**，把它从「通用 agent 框架」变成「面向企业的业务系统生成平台」。

**关键定位：KVVI 是一个独立产品，不是 DSH 的一个模式。**

### 三个进程

| 进程 | 干什么 | 端口 |
|---|---|---|
| **平台服务**（`services/platform/`，Node.js） | 认证、公司/角色/权限、契约存储、发布通道、业务记录 API | 7500 |
| **DSH 运行时**（`vendor/dsh/`） | 承载会话、Agent、工具、模型调用、Web 界面 | 7401 |
| **PostgreSQL** | 三个独立库：平台库 / 业务库 / 审计库 | 54330（试点） |

### 三个身份（不是三个软件，是三扇门）

| 身份 | 从哪进 | 能做什么 |
|---|---|---|
| **owner 所有者** | `/kvvi/login` | 管人、管权限、审批发布、配公司品牌 |
| **builder 搭建者** | `/kvvi/builder/login` | 用自然语言搭系统、提交发布草案 |
| **staff 员工** | `/kvvi/login` | 在已发布的系统里查数据、办业务 |

身份在**登录时绑定**，界面上没有「模式切换器」——走哪扇门就是哪个身份。

---

## 二、做什么（核心能力）

把「用自然语言描述需求」变成「可运行的业务系统」。

### 1. 搭建：自然语言 → 业务系统

搭建者对 AI 说人话，Agent 走一条**六段闭环**生成系统：

```
说人话 → 蓝图 → 类型化命令 → DraftGraph → 校验/影响/预览 → 你点通过
```

中间产出的核心是**五份 JSON 契约**（每份都有 MetaSchema 可机器校验）：

- **数据模型**（business-schema）：实体、字段、关系、状态机
- **表单**（view-schema）：字段控件、校验、显隐
- **流程**（workflow-spec）：审批流、驳回目标态
- **看板**（dashboard）：指标口径、筛选器
- **接口**（tool-spec / app-model-command）：动作端点、命令

### 2. 发布：权限唯一的生效通道

搭建者搭完不能直接上线，必须走**发布通道**：

```
差异报告 → 所有者审批 → 发布
```

跳过任何一环都会被拒。这套设计保证了「未经审批的权限策略不可能生效」。

### 3. 使用：员工用自然语言办业务

发布后，员工在同一界面里用自然语言查询数据、提交表单、走审批——**UI 和 Agent 走的是同一个执行点**，两者判定结果完全一致（这是产品的一条硬性不变量）。

---

## 三、要达到什么目标

1. **让不懂编程的人能搭建业务系统**——自然语言替代写代码和配权限。
2. **私有化交付**——不依赖云端，客户本机部署（第一版 macOS 试点，目标 Linux 企业服务器版）。
3. **安全与隔离**——多公司数据隔离（RLS）、审计防篡改（哈希链）、权限不能自授权/自审批。
4. **可验收**——每一步产出都能被机器校验，闭环每一段都能被判定「是否成立」。

---

## 四、关键技术设计（给程序员看的重点）

- **五份契约 + 双引擎校验**：同一批 MetaSchema 用例，Python 和 Node 两套验证器判定一致，差异会阻断 CI——防止「结构校验」被悄悄绕开。
- **多公司隔离靠 RLS**：业务库用 PostgreSQL RLS 按公司/部门/店铺/本人五档数据范围过滤，且 RLS 是**独立于应用代码的第二层**，测试可以绕过应用层直接验。
- **审计不可篡改**：审计独立成库，追加写 + 哈希链，篡改或删行都能被检出。
- **发布通道是唯一写 `policies` 的地方**：代码层有静态检查（`check_publish_channel.py`）盯着，防止绕过审批直接改权限。
- **UI 与 Agent 同一执行点**：员工在界面点按钮、或让 AI 代办，走的是同一段服务端授权代码，两者允许/拒绝结果一致。
- **令牌非对称签名**：Ed25519，私钥只在平台进程，权限被撤销后旧令牌立即失效。

## 五、仓库结构速览

| 目录 | 内容 |
|---|---|
| `services/platform/` | 平台服务（身份、权限、契约、发布、业务记录） |
| `vendor/dsh/` | DSH fork（运行时，gitignored，经 `forks/dsh/变更/` 可重建） |
| `forks/dsh/` | DSH 的改造点清单、指纹与变更文件 |
| `contracts/` | MetaSchema 契约定义 |
| `工具/` | 校验器、检查器、进度/交付工具（Python） |
| `样例/` | 蓝图样例、黄金样例、行业包样例 |
| `distribution/` | 私有化发行版（`kvvi-admin` 运维入口） |
| `docs/` | 取证、进度、交付文档 |
| `进度.md` | 阶段进度（打开就能看的状态文件） |

## 七、30 秒电梯陈述

> KVVI 是 DeepSeek Harness 的 fork，做成一个企业级的「AI 生成式应用搭建平台」：搭建者说人话，AI 生成表单/审批/看板/接口；发布要过所有者审批；员工用自然语言办业务。多公司数据靠数据库 RLS 隔离，审计哈希链防篡改，目标是让没写过代码的人也能搭出、并安全地运行一套业务系统。
