# KVVI 操作手册

> **阶段七锚点② 的交付物。** 覆盖**所有者 / 搭建者 / 员工**三种角色的完整流程。
>
> 本手册只写**做得到的事情**与**做不到的事情**。凡是产品未兑现的能力，
> 写在这里而不是等交付后被发现 —— 见每节末尾的「本角色做不到什么」。

---

## 一、开始之前：三种角色分别是谁

| 角色 | 用哪个入口 | 能做什么 | 不能做什么 |
|---|---|---|---|
| **所有者** | 搭建引擎（BUILDER） | 授予/回收搭建权限、批准安全敏感变更、配置全部业务权限 | 绕过契约校验；以「批准」替代基础授权 |
| **搭建者** | 搭建引擎（BUILDER） | 在所有者设定的范围内搭建系统、配置**员工**业务权限 | 扩大自己的权限、批准自己的变更、凭搭建权限读业务数据 |
| **员工** | 工作模式（USER） | 在业务权限范围内读写业务数据、办业务 | 看到任何搭建能力；越出数据范围 |

> **模式（Gateway）在会话创建时绑定，会话内不可变更**；公司同理。
> 要换模式或换公司，**新建会话** —— 产品里不存在「切换」这个操作。

## 二、所有者：从零到可用

### 2.1 部署

```bash
./scripts/kvvi-up.sh          # 构建并启动两个进程，等健康检查通过
./scripts/kvvi-up.sh --status # 只看状态
```

**判定标准是「两个容器的健康检查都通过」，不是「容器 Running」。**
平台服务进程与运行时进程分属两个容器，**没有共享可写文件系统**。

### 2.2 首次上线前必须做的三件事

| # | 事项 | 做不了会怎样 |
|---|---|---|
| 1 | **提供签名私钥**（`KVVI_SIGNING_KEY_PATH`，运行期挂载） | 生产环境下进程**起不来**（刻意如此：现场生成一把新密钥会让所有已签发令牌静默失效） |
| 2 | **确认平台库、业务库、审计库是三个独立库** | 审计与业务同库时，「审计不可篡改」只剩一句纪律 |
| 3 | **确认数据归属**（`docs/数据归属表.md`） | 保留期未定则不能对外承诺合规 |

### 2.3 授予搭建权限

搭建权限**只能由所有者授予**，且是所有授权动作中唯一不可代授的一项。
每一次授予与回收**都会留痕**（谁、何时、授予了谁）。

### 2.4 批准安全敏感变更

安全敏感变更（新增权限、放宽数据范围、启用工具、发布契约）**必须由所有者批准**，
且：

- **提出者本人不能批准自己的变更**（自审批被拒并留痕）；
- **批准不能替代基础授权** —— 一条越权的操作，即使所有者批准了，仍然被拒。

### 2.5 所有者做不到什么

- 不能改地基（身份模型、多公司隔离、授权判定、金额精度、终态语义、审计、网关分类、签名密钥管理）。
- 不能读或删审计（审计读权限与搭建权限分离）。
- **不能防御已批准插件对活跃会话令牌的冒用** —— 这是两进程划分的已知边界，
  不是待修缺陷（见《交付文档》第五节）。

## 三、搭建者：把需求变成系统

### 3.1 完整流程（五个 Skill，顺序不可跳）

| 步 | 做什么 | 产出 | 校验强度 |
|---|---|---|---|
| 1 | **听懂**：复述业务需求，歧义处提问 | `00-需求.md` | — |
| 2 | **建模** `data-model` | `business-schema` Spec | **完整校验** |
| 3 | **表单** `form-builder` | `view-schema` Spec（`FORM`） | **完整校验** |
| 4 | **流程** `workflow-builder` | `workflow-spec` Spec | 仅结构校验 ⚠️ |
| 5 | **看板** `dashboard-builder` | `view-schema` Spec（`LIST`）+ 口径登记单 | **完整校验** + 不变量判定 |
| 6 | **接口** `api-spec` | `tool-spec` + `app-model-command` | 仅结构校验 ⚠️ |
| 7 | **交付**：写进工作区，出交付说明 | 原型目录 | — |

⚠️ **第 4、5 步里有一处必须知道**：`workflow-spec` 与 `tool-spec` / `app-model-command`
**只有结构校验**（契约没有语义模块）。所以「结构通过」**不等于**「通过 MetaSchema 校验」。
搭建者需要按 Skill 里的人肉自查清单再过一遍 —— 那几类问题机器查不出。

### 3.2 口径与看板

- 聚合口径（指标怎么算）在**构建期写死**，只有持有构建权限的人能改；
  员工侧改不了，因此**天然可审计**。
- 每条口径在发布前必须过 **§9.8.1 不变量**：
  *能看这个汇总的人，必须同样能看构成它的每一条个体数据*。
  违反的配置**一律拒绝发布，没有审批放行路径**。
- **不要用「把查询范围改小」来规避权限** —— 那正是那条不变量要拦的攻击。

### 3.3 行业扩展包

行业内容（如家具「报货申请」的字段与口径）**只能放在行业扩展包里**：

```
样例/行业包/<包名>/          ← 行业词在这里是合法的
```

**代价是地基必须一动不动** —— 有执行点复核，不是承诺。

### 3.4 搭建者做不到什么

- 不能为自己（或关联账号）配置业务权限；
- 不能批准自己提出的安全敏感变更；
- **不能凭搭建权限读生产业务数据** —— 搭建权限 ≠ 数据权限，
  要读业务数据必须有单独授予的业务权限；
- 不能安装或注册插件、不能改变工具属于哪个网关。

## 四、员工：在系统里办业务

### 4.1 日常操作

在工作模式会话里用自然语言办事：

| 想做什么 | 说明 |
|---|---|
| 查状态 | 「这单到哪一步了」 |
| 查记录 | 「查一下这条记录的历史」 |
| 看汇总 | 「我这个月做了多少」—— **只能看已定义的聚合口径**，不能自由聚合 |
| 新建 | 走类型化命令，必填校验由服务端执行 |
| 修改 | 受状态机约束；**终态不可写** |
| 流程 | 提交、撤回、审批 —— 当前状态下能做什么由流程定义 |

### 4.2 员工看不到什么

**员工会话里一个搭建工具都没有**，这不是「界面藏起来了」：
工具集由**产品级分类**（冻结常量）与实际启用白名单的**交集**决定，
交集只减不增 —— 把全部工具都启用，员工侧也拿不到搭建工具。

### 4.3 员工做不到什么

- 越出数据范围（五档：本人 / 所属店铺 / 部门 / 部门及下级 / 公司全部）——
  超范围读不到，**且与「不存在」返回同样的结果**，避免被用来试探；
- 改数据范围之外或终态的记录；
- 对需要确认的不可逆动作，未经确认就直接生效（未确认只产生草稿）。

## 五、访客：填表（不是「公开链接」）

### 5.1 怎么用

访客**没有账号**。链接由**有写权限的员工或所有者**生成后定向发送。

| 约束 | 说明 |
|---|---|
| **谁能签发** | 必须对该表单有**写权限**；只有读权限的**不得**签发 |
| **能填什么** | 链接显式绑定公司 + 系统 + 表单 + 允许写入的字段集 + 允许的动作 |
| **归属算谁** | **由服务端按签发人的归属确定**，访客不得覆盖 |
| **有效期** | 必须有到期时间，且有产品级上限 |
| **可撤销** | 生成者可随时吊销；**签发人停用或权限回收时，其名下未提交链接全部失效** |
| **能做什么** | **只填这一张表单** —— 不能浏览列表、不能查询、不能与 Agent 交互 |

### 5.2 责任边界（必须让签发人知道）

> 追溯单位是「**签发人 + 链接 ID + 提交通道**」。
> **不承诺区分访客个体** —— 同一链接被转发给多人时，多次提交都只指向同一签发人。

### 5.3 访客提交的内容是不可信数据

访客提交的文本**进入 Agent 上下文时一律视为不可信数据**，
**不构成执行授权**。产品**不声称**它不会被模型当作指令
（那在工程上做不到）—— 防护建立在**执行前确认/审批**上。

## 六、出问题先看哪里

| 现象 | 先看 |
|---|---|
| 容器起不来 | `./scripts/kvvi-up.sh --status`；平台 `/healthz` 的 `signingKeyMounted` |
| 某个账号「什么也看不到」 | 数据档位是否配了；**是不是被拒绝了但看起来像没数据** |
| 拒绝理由看不懂 | 响应里带**错误类别**与**双方版本码**（授权版本 / 契约版本分别给出） |
| 提示平台不可达 | 离线时**缓存窗口内**可降级放行，**超窗失败关闭**；窗口期内放行的操作会标注「离线期放行」 |
| 怀疑审计被改过 | 跑一次链校验 —— 改内容、删中间一条都会被检出 |

## 七、本手册不覆盖什么

本手册描述的是**当前已经交付的能力**。以下**未交付**，不要按已交付使用：

- 访客**界面**（后端接口与全部负向测试已交付，界面未做）；
- 审批流**运行时**执行器（契约层已交付）；
- 附件上传；付款流程；
- 环境晋级、备份恢复、第二行业验证（已移出首版）。
