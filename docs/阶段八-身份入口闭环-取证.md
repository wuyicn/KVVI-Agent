# 阶段八 · 身份入口闭环 —— G6 取证

> 补充需求 v1.0 的阶段八可执行判据。当前结论：**G6 通过**。
>
> ```bash
> python3 工具/check_stage8.py
> ```

## 验收结论

普通员工不能通过界面入口、登录 API、已建立会话或 DSH 运行时预设获得搭建能力。
判据不是“前端隐藏了按钮”，而是四层分别失败关闭：

| 证据层 | 可重跑证据 | 已证明的边界 |
|---|---|---|
| 角色策略 | `mode-policy.test.mjs` | Builder 资格由公司所有者在服务端授予；按公司隔离；收回后终止 Builder 会话并提高授权版本 |
| 界面与 API | `login-gate.test.mjs`、`auth.test.mjs`、`gateway.test.mjs` | Worker / Builder 独立入口；员工伪造 Builder 意图被拒；员工工具集中无搭建工具，错误网关调用留痕 |
| 会话与运行时 | `runtime-routing.test.mjs`、`mode-router.spec.ts` | 浏览器的 `x-kvvi-*` 全部删除；平台按已验证的公司、用户、会话和模式重签；`USER -> kvvi-worker`、`BUILDER -> kvvi-builder`；会话 ID 按公司、用户和模式隔离；跨模式 prompt/list/control/fork 及生命周期事件流失败关闭 |
| 拓扑 | `check_topology.py --static` | 平台是唯一对外入口，runtime 不映射宿主端口，不能绕过平台直连 |

检查器会重建 DSH fork、核对 48/48 文件指纹、离线安装锁定依赖，再运行模式路由测试。
它还把平台实际签出的 USER 头交给 DSH 插件验签，要求结果必须是
`kvvi-worker`；两侧协议或映射只要有一边漂移，G6 就失败。

## 失败关闭行为

- 普通员工请求 Builder 登录：`KVVI_BUILDER_ACCESS_REQUIRED`；
- 缺少、过期或被篡改的平台运行时上下文：HTTP 401；
- 请求体试图指定另一个 preset：服务端覆盖成当前模式固定 preset；
- 会话建立后试图跨模式切换 preset：`KVVI_PRESET_LOCKED_TO_SESSION_MODE`；
- 已知其他用户或其他模式的 DSH 会话 ID：`KVVI_SESSION_ACCESS_DENIED`；
- 上游通用插件管理 Remote 与界面：`KVVI_PLUGIN_MANAGEMENT_DISABLED`，等待阶段十二的所有者审批与签名包通道；
- 当前 DSH fork：`KVVI_SESSION_FORK_DISABLED`，在 fork 目标 ID 能由服务端安全命名之前不开放；
- 直接访问 runtime：部署拓扑不暴露宿主端口，且插件要求有效签名上下文。

## 本阶段没有主张的内容

G6 只关闭“谁能进入哪种模式，以及运行时实际加载哪种预设”。它不代表以下后续目标已经完成：

- 搭建者生成的系统已经能作为表单、列表、流程和看板运行（阶段九 / G7）；
- 所有者已有完整员工、角色和权限管理界面（阶段十 / G8）；
- 私有化安装、升级、备份、恢复、回滚已经完成异机验收（阶段十一 / G9）；
- 离线签名 Skill / Plugin 包已经能安装、启用和回滚（阶段十二 / G10）。

因此，“G6 已完成”不能表述为“产品闭环或发行版已经全部完成”。
