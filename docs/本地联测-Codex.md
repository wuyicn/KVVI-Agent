## 建议顺序

1. **先看员工读面**：用 `staff-view` 打开已发布的客户系统，查看列表和一条详情；在对话中问「列出客户系统的字段及字段编码」，再让它按列表里真实的记录号读取同一条记录。预期能读到授权字段和记录内容，记录号无需手工换成 UUID。
2. **再测权限**：同一员工尝试修改联系人，预期被拒绝；`staff-none` 访问同一系统也应被拒绝。不要把拒绝当成系统故障，也不要把空列表当成权限验证成功。
3. **最后测写入**：用 `staff-edit` 新建一条名称以「联测-」开头的客户记录，记下返回的记录号；按该记录号读回、修改联系人、再次读回。预期每一步都明确返回成功，修改后的值可见。只操作自己的联测记录。
4. **看角色与品牌**：员工页面不出现模式选择器，设置中只列出绑定的工作模式；搭建者从专用入口进入搭建模式。所有者查看品牌页，核对公司名、标语、浏览器标题与员工页面一致。如果试改品牌，先记下原值，测试后恢复。

搭建者的生成、提交发布以及子表业务可另做一轮测试。子表尚未具备契约能力，不能把订单明细的失败记成这一轮已修问题的回归。
