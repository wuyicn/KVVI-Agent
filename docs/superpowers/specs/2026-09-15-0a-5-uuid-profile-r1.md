# 0A-5 UUID 格式剖面 r1（Kimi I-1 修复候选）

适用套件：0a-full-r1。该文为PR #6候选设计的补充，随PR #7交付修复接受负责人审查；并非已批准基线。来源：Kimi针对443c875的独立评审I-1，主协调者复现了Python拒绝URN而Ajv接受URN的差异。

所有 `format: uuid` 必须启用本剖面：字符串恰为ASCII十六进制的8-4-4-4-12五组，以ASCII连字符分隔，总长度36。允许十六进制大小写、nil及任意位值；不额外限制UUID版本或变体位，不做大小写归一。拒绝URN前缀（任意大小写）、花括号、前后空白/换行、无连字符形式、非ASCII十六进制和不正确长度。

`type`约束仍由Schema承担；格式检查器对非字符串不另作类型判定。格式解析不强转、不修改输入。两真实引擎使用独立实现及相同固定预期验证。Python复制core checker实例映射后覆盖uuid，仅本套件生效；Node在本套件Ajv实例覆盖uuid。date/date-time继续复用原剖面。

本规范适用于13份协议及其嵌入定义和共享引用中的全部uuid字段。离开仓库验证器使用第三方引擎时，也必须安装等价格式剖面并启用格式断言；只装载JSON Schema而沿用宿主默认uuid规则，不构成本套件验证。

原core-r1 Schema、工具、向量、指针和历史证据均不修改；其同类UUID缺口单独登记。迁入三份协议/common的JSON约束仍仅有URN命名空间差异，但full验证器新增明确的uuid格式行为收紧，不再声称所有格式行为与core相同。

同批M-1修复：view.addNode的componentName首字母必须大写，与PRD §7.21及ViewNode一致；其余注册表存在性/状态检查仍属L责任。以上修复不批准合并、运行时或生产验收。
