## 建议测试

1. 员工：在会话输入“登记客户青禾设计，联系人王女士”，核对登记弹窗；也可点击“边聊边填”或切换完整表单页，确认填写内容保留，再提交。
2. 打开客户记录，查看登记结果；选中客户后回到会话，输入“把跟进状态改为已成交”，核对修改并保存。
3. 切换请假申请，检查另一种业务表单和记录页。
4. 顶部“体验搭建者”：查看业务配置，增加或调整字段、新建业务，提交发布预览。
5. 顶部“体验所有者”：查看待发布内容，批准示例版本，再切回员工观察变化。

体验角色仅用于原型评审，不代表正式系统允许切换身份。示例业务数据只在当前页面内，刷新即重置；右侧标签、分栏比例、浮窗位置与展开/全屏模式沿用DSH的本地布局保存。自然语言仅支持示例规则，没有连接真实AI、权限、数据库或发布服务。原有7500服务保持不变。

## 2026-10-08 接入 DSH 右侧源码

7506直接导入 `vendor/dsh/packages/client/ui-sidebar-right` 的 `RightbarSeat`、类型注册表、会话store、导航controller、`useTabInfo` 工厂及开始页；标签、分栏、拖拽、浮窗、标题、提示和主题来自原有 `ui-dockkit`、`ui-primitives`、`ui-theme` 源码。

业务扩展分成“注册类型”与“提供内容/标题”两步：表单和记录列表为页面，记录详情以稳定地址打开。重复打开同一记录会定位原标签；聚焦详情后会话客户同步切换；提交表单用对应详情替换提交来源标签。面板布局按体验身份、业务和会话分别保存，继续使用源码的两栏上限、开始页关闭规则和小屏自动全屏。

原型宿主仍负责外层布局、宽度调整和业务草稿，并用小型React槽位桥提供原组件所需的hooks。这里没有启动完整Cordis插件运行时，也没有连接文件、终端、浏览器或后台资源服务。业务配置标签只在搭建者示例中注册。窄屏缩小时补充当前标签定位，避免当前内容的标签被挤出视野。

右侧默认展示为单栏，表单、记录和详情使用顶部标签切换。分栏仍可主动开启，但不作为默认评审布局；2026-10-08已把先前双栏测试状态合并，保留标签、两条示例记录和未提交草稿。

可重点测试：打开右侧开始页 → 表单/业务记录 → 新标签 → 分栏；拖动标签到会话上形成浮窗，再收回；切换业务/身份后返回；关闭并重开面板；从不同客户详情切换到会话修改，确认修改对象正确。布局会恢复，但刷新后的旧示例记录详情会明确显示数据已重置。

检查：`npm test`（6项DSH实际store/controller集成检查）、`npm run build` 与 `npm run test:sites`（4项）通过；桌面与手机浏览器流程见QA记录。此项完成的是7506的右侧前端接入，尚未合入正式Harness。
