## 检查与调整记录

1. [P2，已修复] 首轮正文与字段偏小，信息灰度偏浅。
   - 证据：builder-desktop.jpg 对照 01-builder.png，主要业务信息采用 12–14px，与源稿的易读层级差距明显。
   - 调整：业务正文 14–16px；字段 14px；主标题 21–30px；辅助文字 12–13px，调深灰色。
   - 复查：builder-desktop-v2.jpg、builder-final.jpg；信息层级清楚，表单和输入区无覆盖。
2. [P1，已修复] 初次员工效果沿用搭建者历史，容易混淆权限和工作内容。
   - 证据：employee-desktop.jpg 左侧出现「调整客户登记表」「设置销售可见范围」。
   - 调整：会话按身份与业务分别保存，员工展示登记/查询历史；员工不显示成员管理和搭建按钮。
   - 复查：employee-desktop-v2.jpg、employee-final.jpg，只有员工业务会话；模拟发布前后的构建会话不进入员工对话。
3. [P2，已修复] 狭窄窗口中会话占用过高，发送区和业务预览被挤到下方。
   - 证据：tablet.jpg、mobile-before.jpg。
   - 调整：窄屏会话固定约 510px，消息内部滚动；简化提示；表单区接在会话后并可滚动。
   - 复查：tablet-final.jpg、mobile-after.jpg。发送区可见，业务预览可达，无水平溢出。tablet-after.jpg 是调整 viewport 过程中的 489px 过渡截图，不作最终证据。
4. [P2，已修复] 示例状态曾按整个页面保存记录和权限范围，切换业务可能串入。
   - 调整：按业务分别保存记录、草稿、可见范围及操作选项；搭建会话与员工会话使用不同键。
   - 复查：客户提交 1 条记录后，切入请假「我的记录」仍为 0；客户草稿切换业务后保留；新建供应商登记后标题、表单及会话同步绑定。

## 五项视觉表面

- 字体：中文系统字体 PingFang SC / system sans；标题加重，业务正文 14–16px；长文本换行、表单层级和禁用负责人状态已检查。相比旧图缩小一些展示尺度以容纳业务会话层级，这是本轮密度调整。
- 布局：沿用白底、浅蓝侧栏、会话/表单分栏；侧栏从来源约302px改252px。新增业务内会话、身份徽章和表单/权限/发布检查标签属有意调整。员工业务区域更宽，助手区域更窄。
- 色彩：主操作 #0066ff；浅蓝选中及会话背景，细灰蓝边线；绿色用于发布与可用状态，灰色用于草稿和辅助信息。增加焦点描边；未完成完整 WCAG 对比度审计。
- 资产：使用生产代码 Brand.tsx 的原始 KVVI_MARK_PATH，原样保存为独立 SVG 图片；该现有 KVVI 标识与旧图略有不同，是使用现行品牌源，未重新绘制。Lucide 同族线性图标；无生成插画、CSS 仿制标志或图片占位。
- 文案：角色、当前业务、草稿、发布后效果和权限范围明确；员工短句直接指向表单/记录。移除日常流程中的模型名、工具和工作区术语。

## 保留边界与后续

- 原型会话为预设交互；不代表通用 AI 解析能力。
- 权限为界面设置示例，没有真实授权或安全执行；发布、记录和草稿为页面内演示，刷新重置。
- 没有全面验证键盘、屏幕阅读器或高倍率缩放；正式实施前补齐对话框焦点管理、键盘退出和账户/权限错误的服务联动。
- 后续按用户确认的 UI 接入实际账号身份、授权业务清单、表单预览和会话绑定。真实 employee 仅展示已发布且授权业务。

核心 P0/P1/P2 视觉和演示流程问题已处理；用户的设计确认待反馈。最终结果：passed。
