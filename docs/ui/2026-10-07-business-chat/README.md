# 业务与会话结合 · UI 原型

本地体验：http://127.0.0.1:7505/

本轮依据用户提供的 KVVI-UI-design-v1.zip，优先做可点击界面供确认。正式服务和真实权限未修改。原型按钮只改浏览器中的示例状态，刷新后重置；会话使用预设回复，没有调用真实 AI 或业务接口。

## 设计方向

- 以业务为入口：先选择业务，该业务的会话、表单和结果一起切换。取消「工作区」作为日常业务概念。
- 搭建者：左侧业务与搭建会话，中间描述需求，右侧预览表单；可直接添加字段、设置员工范围、试填和查看发布后效果。
- 员工：表单与业务记录在主区域，当前业务助手在右侧。助手给简短结果并提供直达表单或记录的按钮。
- 搭建者和员工分别显示身份、入口和会话。员工不显示搭建记录、系统结构编辑或成员管理。
- 搭建资格、业务使用权限和数据范围分别说明。未获搭建资格时，说明当前身份和可用业务，并提供账号切换及开通说明。
- 模型、工具和工作区等高级配置折叠到设置。原型顶部的三个视角按钮仅用于评审，不是正式授权或身份切换。
- 正式员工入口只展示已发布且有权限的业务；原型允许查看当前草稿的员工效果，并标为「员工效果预览」，其他未发布草稿不进入员工业务列表。

## 建议体验顺序

1. 搭建者：点「新建业务」，填写名称；尝试在会话里增加备注，或直接点「添加字段」。查看表单同步变化。
2. 打开「员工权限」，修改数据范围；点「试填体验」；点「提交发布」查看确认页及员工效果。
3. 员工：点「登记一个新客户」，核对示例填入内容，再点提交登记。检查结果直达「我的客户」。保存草稿后切换业务再返回，草稿保留。
4. 顶部点「查看无搭建权限」，体验没有搭建资格时的解释和去向。

原型不演示真实权限执行、审批发布、数据库持久化或通用 AI 理解。成员设置仅改变演示状态，不代表真实授权。

## 当前正式入口发现

本次在 7500 的「业务 → customer → 记录」复现：`KVVI_NOT_ALLOWED：没有 customer 的 read 动作权限`。这是记录读取权限不足，不能据此认定搭建资格缺失。本轮尚未核实当前浏览器账号身份及其搭建资格，未自动扩大权限。

现有页面未清楚区分搭建身份与业务使用权限，且将业务藏在左下角，客户系统仍展示内部名 customer。截图见 current-entry.jpg、current-permission.jpg。

## 全局字体更新

按用户要求统一全局字体、字号、字重与行距。正文和输入16px，按钮与字段标签14px，辅助说明13px，状态12px，标题20–28px。员工会话与搭建会话使用相同正文尺度，小窗口主要通过排布和滚动容纳文字。最新截图在prototype/typography-review/after-final.jpg、employee-final.jpg；详情见prototype/design-qa.md的最新复核。

## 最新迭代：精简界面和直接编辑字段

顶部改为「搭建会话」「表单预览」，移除重复说明并压缩空白。保留16px业务正文和输入文字，1280×720窗口可完整看到默认五字段卡片及「添加字段」。

搭建者点击字段名称或铅笔，可修改名称、填写方式、必填和单选选项；保存后表单即时更新，会话只显示修改结果。重命名保留页面内已有草稿和示例记录；空名称、重名、空选项及重复选项会阻止保存。员工和试填视角没有字段编辑入口，提交时按当前必填设置校验。

建议体验：先点「联系人」改名并切换必填，再点「跟进状态」修改选项；保存后看会话结果，切换员工视角试填。最新截图在prototype/editing-review/desktop-final.jpg、field-editor.jpg、mobile-editor.jpg。浏览器已验证字段修改、草稿及记录保留、必填阻止提交、修改后选项提交和业务隔离；构建通过。仍为页面内演示，刷新重置。
