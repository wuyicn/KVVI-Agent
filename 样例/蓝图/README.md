# `0D-1` 蓝图闭环样例

> **阶段三锚点④ 的取证。** 六段自查见 `docs/AI蓝图闭环-0D-1.md`。

## 复现

```bash
python3 工具/check_blueprint.py 样例/蓝图/通用事项管理系统   # 闭环是否闭合
python3 工具/蓝图样例.py --check                             # 样例是否被手改过
bash 工具/check_blueprint_自测.sh                             # 反向测试 13/13
```

## 这是「整包建系统」，不是又一份契约

| 文件 | 是什么 | 契约 |
|---|---|---|
| `00-需求.md` | **说人话**：业务原话 + 待确认的问题 | 无（自然语言） |
| `蓝图.json` | 要建什么：应用、id 表、五部分产出物、命令溯源 | 本项目定义 |
| `命令/*.command.json` | **类型化命令**，35 条，按文件名顺序即执行顺序 | `app-model-command/v1alpha1` |
| `影响.json` | **影响报告**：动到了哪些资产、各自摘要 | `evidence-bundle/v1alpha1` |
| `预览/*.html` | **预览**：由 `view-schema` 节点树渲染，逐字节可复现 | 本项目定义 |
| `审批.json` | **你点通过**：绑定到同一份 DraftGraph 摘要 | `approval-attestation/v1alpha1` |

**产出物本身不放在这里。** `蓝图.json` 的 `artifacts[].path` **引用**
`样例/business-schema/`、`样例/view-schema/` 等目录里的那几份 ——
一份产出只有一个家。蓝图把它们的摘要算进自己的 DraftGraph 摘要，
摘要对不上就报「影响报告是旧的」。

## 为什么整份目录是生成的

`工具/蓝图样例.py` 生成全部 41 个文件。因为里面到处是**摘要链**：
产出物摘要 → DraftGraph 摘要 → 影响报告 → 审批绑定。

手写它等于手工维护一条链，链条任意一处接不上，检查器只报「摘要不符」，
**不告诉你是哪一环**。生成器按正确顺序算，`--check` 还能检出手改。
