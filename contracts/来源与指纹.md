## 五·补 · 契约层的一次**有意扩展**：`FieldPolicy.required_field`

> 这一节记的是一次**对并入基线本身的修改**。并入时它宣称「与源仓库逐字节一致」——
> 那句话从这一刻起不再成立，而**必须成立的是「每一处偏离都有记录」**。

### 改了什么

`contracts/meta-schemas/0a-full-r1/permission-spec.v1alpha1.schema.json`：

| 项 | 改前 | 改后 |
|---|---|---|
| `FieldPolicy.properties` | `policy_code, role_code, role_ref, dimension, resource_ref, subresource, field_mode` | 同上 **+ `required_field`** |
| `FieldPolicy.required`（必填键） | 7 项 | **不变** —— 新属性是**可选**的 |
| `field_mode` 枚举 | `DENY / HIDDEN / MASKED / READ_ONLY / EDITABLE` | **不变** |

```json
"required_field": { "type": "boolean", "default": false,
                    "description": "这一档是否要求该字段**有值**（按角色）" }
```

**向后兼容**：既有契约不带这个键，一律保持有效 —— 已用真契约（试点那六份）复验过结构层。

### 为什么要改（而不是绕开）

「必填」在氚云是**按角色/节点可配**的（「新增数据权限」「查看编辑数据权限」），
而我们此前只有**模型层**的 `Field.required`（对所有人成立的下限）。
两者不冲突 —— 模型层是下限，权限层再收窄 —— 但**权限层没有地方放这个事实**：

- `business-schema.Field.required` 是全局的，改了会影响所有人；
- `policies` 那张表里加一列只能让**运行时**支持，而契约层写不出来 →
  搭建者表达不了，也就等于没做（「唯一生效通道是发布」）。

### 为什么不并进 `field_mode`

「可见性」与「必填」是**两个正交的轴**。挤进同一个枚举会丢掉组合：
「**只读**且必填」表达不了 —— 而它合法且常见：值由别人或流程填，
但在你这一步它必须已经存在（审批节点上「确认金额已填」就是这个意思）。

### 为什么叫 `required_field` 而不是 `required`

JSON Schema 自己有一个 `required` **关键字**（同级那个数组）。同一个对象里
`properties.required` 与 `required: [...]` 并排，读起来像笔误 ——
而这份文件的读者包括下一个照着改 schema 的人。

### 连带改的

| 文件 | 改了什么 | 为什么 |
|---|---|---|
| `manifest.json` | `resources['permission-spec.v1alpha1.schema.json'].sha256` | `tools/meta-schema-full/0a-full-r1/verify.py` 逐字节核对每个 schema 与 manifest 的一致性 |
| `契约资产清单.sha256` | 全量重算（1340 项） | G1 指纹清单；`--verify` 现为 **0 异常** |

⚠️ **`suite_revision` 不升版**（仍是 `0a-full-r1`）：本次是**向后兼容的可选属性**，
既有契约一律有效；内容变了这件事由 manifest 里的 per-resource `sha256` 表达 ——
那正是那个字段存在的意义。

⚠️ **`tools/meta-schema-full/0a-full-r1/verify.py` 在本仓库跑不起来**
（缺 Python 的 `jsonschema` 模块，属既有状况）。所以这次改动**没有**经过它复核；
能跑的复核是：① 官方 CLI 对 business-schema 仍 `valid: true`；
② 搭建者侧的 `check-full-r1.mjs`（用同一份 schema 编译 ajv）对六份真契约 60/60。

### 还没做（第二次扩展，不与这次合并）

「**某个状态下必填**」（氚云的「节点上配置」）需要给 `FieldPolicy` 再加一个状态 ——
`FieldPolicy.subresource` 是 `{type: FIELD, code}`，**没有地方放状态**
（FLOW 策略才有 `{type: STATE, code}`）。这次没做，也没塞一个恒为 null 的键假装支持。
