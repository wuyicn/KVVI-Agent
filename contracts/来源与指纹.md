## 四、⚠️ 与 PRD §5.3 的一处**偏差**（记录在案）

**PRD §5.3 写的 KVVI-Agent 侧权威路径**：

> `contracts/meta-schemas/`、`contracts/validator/node/`、`contracts/validator/python/`、`contracts/tests/`

**实际并入路径**：

> `contracts/meta-schemas/`（✅ 一致）、`tools/meta-schema/node|python/`、`tests/meta-schema*/`

### 为什么偏离

`verify.py` 与 `test_structure.py` **硬编码**了原路径：

```python
# verify.py:190-193
files += list((ROOT / 'tools/meta-schema-full/0a-full-r1').glob('*.*')) + ...
files += [ROOT / 'tools/meta-schema/node/package-lock.json',
          ROOT / 'tools/meta-schema/python/requirements.lock', ...]

# test_structure.py:30
tool = ROOT / 'tools/meta-schema-full/0a-full-r1/verify.py'
```

按 §5.3 的路径搬 → **验证器直接跑不起来**（实测：`FileNotFoundError`）。

### 取舍

| 方案 | 可字节比对 | 验证器可跑 |
|---|---|---|
| 按 §5.3 路径搬 | ❌（要改代码就不一致了） | ❌ |
| **保持原布局（采用）** | ✅ **1331/1331** | ✅ **6 测试 OK** |

**保持原布局** —— 因为 §5.3 的路径是**在看不到资产的情况下写的**
（这正是冻结记录里「外部事实从未被任何评审者核实」所指的那类问题）。
**代码能跑 + 字节可验** 优先于路径好看。

> **§5.3 的 validator 路径应记为「待修订」** —— 属 PRD 层面的小修正，
> 不阻塞实现。**不要手改 §5.3**：PRD 已冻结，改动须走《SOP v1.1》的修订流程。

## 六、验证器自述的已知局限（照抄，不美化）

> - `M-4 remains OPEN`

> - `No complete validator for ten new protocols`

并且它明确标记：

| 字段 | 值 | 含义 |
|---|---|---|
| `semantic_validation_complete` | **`False`** | **语义校验未完成** |
| `runtime_verified` | **`False`** | 未做运行时验证 |
| `release_approved` | **`False`** | **未批准发布** |
| `validation_scope` | `'structure'` | 只覆盖**结构** |

> **这一点很重要**：6 个测试全过**不等于**契约层已验证完毕。
> **验证器自己就声明了它只做结构校验**，语义与运行时均未覆盖。
> **不要把它读成「契约层已就绪」。**
