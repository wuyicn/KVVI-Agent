# 接口定义生成（api-spec）

把模型和界面绑到一份**写明了的**接口契约上。没有契约的原型，
前后端各按自己理解实现，对接时才发现字段名和语义都不一样。

契约先写，代码照着写——不是反过来。

## 何时用

- 用户要对接外部系统：*「生成这些页面对应的 API 定义」*
- 用户要把原型给开发团队实现
- 原型里有跨边界的数据流（浏览器 ↔ 服务端、本系统 ↔ 外部系统）

## 前置

模型未定**先跑 `data-model`**。接口形状由模型决定：
实体 → 资源，关系 → 子资源或查询参数，状态机 → 动作端点。

## 生成规范

### 1. 资源设计

**资源是名词，复数是集合**：

| 操作 | 方法与路径 | 语义 |
|---|---|---|
| 列表 | `GET /申请` | 分页查询 |
| 详情 | `GET /申请/{id}` | 单条 |
| 创建 | `POST /申请` | 新建 |
| 全量更新 | `PUT /申请/{id}` | 整体替换 |
| 部分更新 | `PATCH /申请/{id}` | 改若干字段 |
| 删除 | `DELETE /申请/{id}` | 软删除优先 |

### 2. 状态迁移用动作端点，不要用 PATCH 改状态

这是最容易做错的地方。`状态` 是**结果**，不是**入参**：

```
❌ PATCH /申请/{id}   { "状态": "已通过" }     ← 绕过审批规则
✅ POST  /申请/{id}/通过  { "意见": "..." }
✅ POST  /申请/{id}/驳回  { "意见": "...", "驳回原因": "..." }
```

用 PATCH 直接改状态会**绕过审批人解析、权限校验和审计记录**。
每个状态迁移一个动作端点，让服务端自己决定状态怎么变。

### 3. 请求与响应

```yaml
POST /申请
请求:
  content-type: application/json
  body:
    申请人id: { 类型: string, 必填: 是 }
    金额:     { 类型: integer, 必填: 是, 说明: "分为单位, >0" }
    明细:     { 类型: array<申请明细>, 必填: 否 }
响应:
  201:
    体: { id: string, 单号: string, 状态: "草稿", 创建时间: datetime }
```

规则：

- **金额一律整数分**，字段名或文档写明单位。浮点金额是对不平账的根因。
- **时间一律 ISO 8601 带时区**（`2026-09-21T13:00:00+08:00`），不用本地化字符串。
- **id 是不透明字符串**，客户端不得解析其结构。
- 请求体与响应体**形状可以不同**：响应带服务端生成字段（id、状态、时间戳）。
- 列表响应统一包一层：`{ 数据: [...], 分页: {...} }`，不要裸数组——
  裸数组以后加不了分页元信息。

### 4. 错误

统一错误体，一个形状覆盖所有失败：

```yaml
错误体:
  错误码: string          # 机器判定的稳定标识, 如 "validation_failed"
  消息:   string          # 给人看, 说清怎么改
  字段错误:               # 仅校验失败时
    - { 字段: "金额", 原因: "必须大于0" }
  追踪id: string          # 用于对日志, 必须返回
```

状态码：

| 码 | 含义 | 何时用 |
|---|---|---|
| 400 | 请求格式错 | 体不是合法 JSON |
| 401 | 未认证 | 无凭据或凭据过期 |
| 403 | 无权限 | 认证通过但该操作不允许 |
| 404 | 不存在 | 或**无权看到**（不区分，避免探测） |
| 409 | 冲突 | 唯一约束、并发版本冲突 |
| 422 | 语义校验失败 | 字段都合法但业务规则不满足 |
| 429 | 频率超限 | 带 `Retry-After` |
| 500 | 服务端错 | 必须返回追踪id |

**403 与 404 的选择很重要**：无权访问的资源返回 404，
避免通过状态码探测「这个 id 是否存在」。

### 5. 分页与并发

- 分页：默认**游标分页**（大表稳定），
  偏移分页只用于必须跳页的场景，并说明深分页代价
- 排序：默认稳定排序（带 id 兜底），否则翻页会重复或漏
- 并发：更新接口带**版本号或 If-Match**，冲突返回 409
  ——无并发控制的编辑会静默覆盖别人的修改

### 6. 鉴权与幂等

- 鉴权方式写明（Bearer token / session / 签名），以及**鉴权与授权分开**：
  能登录 ≠ 能做这个操作
- 每个接口标注**所需权限**，与模型的数据范围权限一致
- **有副作用的接口必须幂等**（创建、支付、发通知）：
  用 `Idempotency-Key` 头，重复请求返回首次结果而不是重复执行
  ——重放导致重复扣款/重复下单是真实损失

## 输出格式

```yaml
资源: 申请
路径: /申请
权限: "申请人可创建; 审批人可动作; 他人只读"
接口:
  - 方法: GET
    路径: /申请
    说明: 分页列表
    查询: { 状态: enum, 部门id: ref, 游标: string, 每页: integer=20 }
    权限: "只返回当前用户可见范围"
    响应: { 200: { 数据: array<申请摘要>, 分页: { 下一页游标: string } } }
  - 方法: POST
    路径: /申请
    说明: 创建申请(草稿态)
    幂等: "Idempotency-Key 必填"
    请求: { 申请人id: string, 金额: integer, 明细: array<申请明细> }
    响应: { 201: 申请详情, 422: 错误体 }
  - 方法: POST
    路径: /申请/{id}/通过
    说明: 审批通过, 服务端按状态机决定迁移
    权限: "当前待审批人"
    幂等: "已通过时重复调用返回 200 同一结果"
    请求: { 意见: string }
    响应: { 200: 申请详情, 409: "状态已变更" }
错误体: { 错误码: string, 消息: string, 字段错误: array, 追踪id: string }
```

## 常见错误

| 错误 | 后果 | 正确做法 |
|---|---|---|
| PATCH 直接改状态 | 绕过审批与权限 | 每迁移一个动作端点 |
| 金额用浮点 | 对不平账 | 整数分 + 写明单位 |
| 列表返回裸数组 | 无法加分页 | 包 `{数据,分页}` |
| 无权返回 403、不存在返回 404 | 可探测 id | 均返回 404 |
| 无并发版本控制 | 静默覆盖他人修改 | 版本号 / If-Match |
| 副作用接口非幂等 | 重放导致重复扣款 | Idempotency-Key |
| 本地化时间字符串 | 时区歧义 | ISO 8601 带时区 |
| 错误体形状不一 | 客户端无法统一处理 | 统一错误体 + 追踪id |
| 鉴权即授权 | 能登录就能改 | 两者分开标注 |

## 交接

接口契约是可交付物，交付时**连同一份 openapi/示例文件写入工作区**，
不要只在回复里贴一段 YAML——回复会随会话消失，文件不会。
