## 三、冻结的**含义**与**不含义**

### 它意味着

- v2.5 的**产品范围、设计决策、红线、验收锚点**已定，实现阶段不再重新讨论
- 全部 8 项红线中，首版生效的 5 条（1/2/3/4/8）**无一可豁免**
- 七阶段的**验收锚点**（§7.1）与**门禁 G1–G5**（§7.5.2）已明确
- 任何后续修订都必须**重新走评审**，不得直接改冻结版本

### 它**不**意味着

- ❌ **不是安全认证**。四轮评审不是正式威胁建模，只是一次独立审阅
- ❌ **不是「没问题了」**。它意味着「在四轮独立评审的覆盖下，已知问题已处理并记录」
- ❌ **不覆盖实现**。文档冻结 ≠ 代码正确
- ❌ **不解除 §9.12 的要求**：进入实现阶段后，**仍应由专门人员按标准方法（威胁建模等）做正式安全评审**

## 四、⚠️ 已知局限（必须读，冻结不掩盖这些）

### L1　v2.5 本身**未经复评**（最重要的一条）

v2.4 经四轮评审后修订为 v2.5，而 **v2.5 的 8 项修订没有任何独立模型看过**。
其中三项是**架构级新增**：

| 新增 | 风险 |
|---|---|
| §4.1.1 部署单元架构声明 | 它把 §9.6.3「技术上不可达」从**期望**变成了**构造性保证**——但这条推理链**没人验证过** |
| §4.6 存储拓扑基线 | 含三条不可协商规则，其中「审计不与业务数据同库」是对 §9.11.2 的**拓扑级修复** |
| §9.4.3 契约版本协商 | 新增的协议不变量，未经验证 |

> **结论：v2.5 是可开工的基线，不是可交付的终稿。**
> 进入阶段一之前，建议**补一轮针对 v2.5 的独立复评**，重点验 §4.1.1 / §4.6 / §9.4.3。
> **本冻结记录存在的前提就是写明这一点。**

### L2　全部外部事实声明**从未被任何评审验证**

PRD 中关于外部系统的事实性声明，**四轮没有任何一个模型能够核实**——
它们看不到 KVVI-Builder 仓库，也看不到 DSH 源码。GPT-5.6 与 Kimi 都**主动声明**了这一点。

| 未验证的声明 | 位置 |
|---|---|
| 「13 份 MetaSchema 已固化、有哈希」 | §5.3 |
| 「双引擎验证器 6 个结构测试全部 OK（2.4s）」 | §5.3 |
| 「DSH 没有多用户和鉴权」的实测结论 | §2.3、§4.3 |
| DSH 仓库体积、源码规模、许可证等实测值 | §6 |
| `0B-x` / `0C-x` / `0D-x` 任务卡的验收标准与工作量 | 全文引用 |

> **这些是 PRD 立论的基础，但它们目前的证据等级是「作者自述」。**
> 阶段一的第一件事（G1、G2）就是把这些变成**可核验的实体**。

### L3　对抗性评审只有**一遍**，不是完整威胁建模

第 2 轮的 GPT-5.6 对抗性审查是**单次独立审阅**，不是系统化威胁建模。
§9.12 已明确要求后续补做正式安全评审——**这条要求不会被冻结解除**。

### L4　同家族弱点（诚实披露）

本 PRD 由 `deepseek-flash` 撰写，而评审阵容中的 `deepseek-v4-pro` 与
`deepseek-r1:32b` **同属 DeepSeek 家族**。同家族模型可能共享盲区——
第一轮 `deepseek-r1:32b` 出现 2 处编造，也说明该家族在本任务上的可靠性波动较大。

**跨家族的三份**（GPT-5.6 / Gemma4 / Qwen3.8 / Kimi-k3）是对冲，但作者与评审者
**不是完全独立的**。

### L5　已知但**未解决**的设计张力（不是缺陷，是取舍）

| 项 | 状态 |
|---|---|
| **§9.10 扩展通道（S3-2）** | 插件是**代码执行通道**。作者是在建立 bundle/plugin 机制**之后**才意识到这一点，§9.10 是**事后补的边界**，其完备性未经专门验证 |
| **7 项转入《技术设计文档》** | 确认凭证签发验签、发布服务读写边界、确认界面防呆、地基不变量机器判定条件、脱敏执行点、密钥轮换信任路径、配置发布签名绑定——**这些在 PRD 里只有约束与目标，没有实现路径** |
| **阶段四五装载偏满** | 13 周内集中全部红线落地与 9 项 0B 地基任务（Kimi 建议的拆分点已写成门禁 G4，但未拆阶段） |
| **Q11 未定** | 私有化交付方式（部署包 / 代部署 / 托管）。**不阻塞阶段一至阶段六** |

### L6　评审模型**会编造**

已知实例：`deepseek-r1:32b` 声称「§5.5 未包含 `money`」（实际在十类枚举内）、
「§3.3 未处理未提交单据」（实际有整行处理）。

**因此本冻结清单存在的意义之一是**：后续若有人引用某条评审结论，
**可以回到指纹固定的原始证据**核对，而不是信任转述。

## 六、如何解除冻结

**冻结不是永久锁定，但改它必须付代价。**

任何对 PRD 的修改，都必须：

1. **新版本号**（v2.6、v2.7……），不得原地修改 v2.5
2. **说明触发原因**——来自哪一条评审发现、哪一次实现中发现的矛盾、或哪一项需求变化
3. **重新跑独立评审**，且评审模型须**至少一个此前未参与该视角的家族**
4. **更新本目录的清单**，并**保留旧清单**——旧指纹是历史版本可追溯的唯一依据

> **唯一允许不经评审的修改**：错别字、链接失效、格式问题。
> 即便如此，也必须**升级补丁版本号并重算指纹**。
