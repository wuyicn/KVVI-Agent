# KVVI 原型交付骨架（templates/）

生成业务系统原型时，把产物写进工作区的下列结构。**留一份骨架在磁盘上**——
原型只存在于回复里就等于没交付，回复会随会话消失。

> ⚠️ 产出是 **JSON 契约**，不是散文 YAML。每一份都是对应 MetaSchema 可校验的
> `*.spec.json`（数据模型 / 表单 / 流程 / 看板）与 `*.command.json`（类型化命令），
> 后缀与校验器、蓝图闭环一致。

## 目录约定

```
<项目名>/
├── 00-需求.md          听懂阶段的产物：业务原话、待确认问题
├── 01-数据模型.spec.json   data-model 的产物：实体、字段、关系、状态机、不变量
├── 02-表单/              form-builder 的产物，每个可写实体一份
├── 03-流程/              workflow-builder 的产物，每条状态机一份
├── 04-看板/              dashboard-builder 的产物
├── 05-接口.spec.json      api-spec 的产物
└── 99-交付说明.md        跑通什么、桩了什么、还差哪些决定
```

## 每个文件的最小要求

| 文件 | 必须包含 | 缺失的后果 |
|---|---|---|
| `00-需求.md` | 业务原话 + **待确认问题清单** | 猜测被当成需求 |
| `01-数据模型.spec.json` | 实体/字段/关系/状态机/不变量 | 下游三样全部失准 |
| `02-表单/*.spec.json` | 字段控件映射 + 校验 + 条件显隐 | 脏数据静默入库 |
| `03-流程/*.spec.json` | 节点/边/**驳回目标态**/测试用例 | 驳回后无处可去 |
| `04-看板/*.spec.json` | 指标**口径** + 筛选器默认值 + 权限 | 会上数字打架 |
| `05-接口.spec.json` | 动作端点（非 PATCH 改状态）+ 统一错误体 | 绕过审批与权限 |
| `99-交付说明.md` | 跑通/桩/待决定三段 | 被误当成可投产系统 |

## 三条硬规矩

1. **不编造用户没说的业务规则。** 不知道的写进 `00-需求.md` 的待确认清单，
   并在交付说明里再点一次。猜出来的审批规则比没有更危险。
2. **金额用 `money` 类型，时间用 ISO 8601 带时区。** 金额**绝不用浮点**（也用不着
   「整数分」的手工换算 —— `money` 类型自带 `precision/scale`，由平台按整数精度
   结算）；本地化时间字符串有歧义。
3. **交付说明必须写明「未验证」的部分。** 原型不是已测试系统，
   不得声称生产可用、不得编造合规结论。

## 用哪一份

- 用户只说了一个业务想法 → 从 `00-需求.md` 开始，走完整五步
- 用户已有模型只缺界面 → 从 `02-表单/` 开始
- 用户要对接外部系统 → 重点在 `05-接口.spec.json`
